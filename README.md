ربات معامله‌گر پایتونی برای صرافی نوبیتکس — استراتژی ترکیبی (تکنیکال)، مرحله‌بندی‌شده: **بک‌تست → Paper Trading (Testnet) → معاملهٔ واقعی (فقط بعد از تایید صریح)**

### 🎯 ویژگی‌های اصلی
- 📊 **Paper Trading روی Testnet** — تست استراتژی‌ها با دادهٔ بازار واقعی، بدون ریسک مالی
- 🔄 **تست چند تایم‌فریم همزمان** — اجرای مترادف استراتژی‌های مختلف در تایم‌فریم‌های متفاوت
- 🔒 **رمزنگاری محلی** — کلیدهای API فقط محلی و رمزنگاری‌شده (هیچ ارسال ابری)
- 📱 **اطلاع‌رسانی تلگرام + تایید دستی** — پیام تلگرام برای معاملات و تایید/رد کاربر
- 🌍 **پشتیبانی فارسی کامل** — رابط کاربری RTL، تقویم جلالی، پیام‌های فارسی
- ⚖️ **مدیریت ریسک پیشرفته** — اندازه‌گذاری موقعیت، محدودیت ضرر روزانه، حداکثر معاملات همزمان
- 🛡️ **احراز هویت Ed25519** — امضای رمزنگاری نوین (استاندارد جدید API نوبیتکس)
- 🧪 **95+ تست واحد** — کیفیت و قابلیت‌اعتماد بالا

## اسکن بازارها و رتبه‌بندی فرصت‌ها

```bash
python scripts/scan_markets.py --resolution 60 --top 15
```

همهٔ بازارهای فعال رو اسکن می‌کنه، اندیکاتورهای هر کدوم رو محاسبه می‌کنه، و بر اساس امتیاز ترکیبی (نوسان + حجم + قدرت سیگنال) رتبه‌بندی‌شون می‌کنه. قدرت سیگنال از توافق سه اندیکاتور مستقل به دست میاد: جهت EMA9/EMA21 (روند)، فاصلهٔ RSI از ۵۰ (مومنتوم)، و علامت هیستوگرام MACD — هرچی بیشتر هم‌جهت باشن، سیگنال قابل‌اعتمادتر تلقی می‌شه. این ماژول فقط برای **شناسایی و رتبه‌بندی فرصت‌ها**ست؛ منطق ورود/خروج قطعی معامله در فاز ۳ (استراتژی‌ها) اضافه می‌شه.

## استراتژی‌های ترکیبی (فاز ۳)

سه استراتژی ماژولار در `src/nobitex_bot/strategies/`، هرکدوم فقط سیگنال و سطوح پیشنهادی SL/TP رو مشخص می‌کنن (اندازهٔ پوزیشن و اعمال قیدهای ریسک در فاز ۵ انجام می‌شه):

| استراتژی | ورود | خروج | SL/TP |
|---|---|---|---|
| `trend_momentum_volume` | کراس EMA9/21 + RSI ۵۰-۷۵/۲۵-۵۰ + تاییدیهٔ حجم | کراس معکوس EMA | ATR × ۱.۵ / ATR × ۳ (نسبت ۱:۲) |
| `mean_reversion_rsi_bb` | لمس باند بولینگر + RSI oversold/overbought | رسیدن به باند میانی | ATR × ۱.۵ / باند میانی |
| `breakout_atr` | شکست کانال ۲۰ کندلی + تاییدیهٔ حجم | فقط از طریق سفارش OCO نیتیو (بدون خروج دستی) | ATR × ۲ / ATR × ۳ (نسبت ۱:۱.۵) |

استراتژی‌ها از طریق `strategies/registry.py` به‌صورت پلاگین ثبت می‌شن (`get_strategy(name)`، `list_strategies()`) — اضافه‌کردن استراتژی چهارم فقط یعنی یک فایل جدید + یک خط در رجیستری.

## بک‌تست (فاز ۴)

```bash
python scripts/fetch_historical.py --resolution 60 --days 365   # اگه قبلاً دانلود نشده
python scripts/run_backtest.py --symbols BTCIRT,ETHIRT,USDTIRT --resolution 60
```

هر ۳ استراتژی روی هر نماد اجرا می‌شن و گزارش مقایسه‌ای (نرخ برد، Max Drawdown، Sharpe Ratio، سود/زیان خالص، تعداد معاملات) چاپ می‌شه. نکات طراحی مهم موتور بک‌تست (`src/nobitex_bot/backtest/engine.py`):

- **بدون look-ahead bias**: سیگنال از رویِ کندل i محاسبه می‌شه ولی اجرا در قیمت *باز شدن* کندل i+1 شبیه‌سازی می‌شه (الگوی Jesse از فاز ۰)
- SL/TP در برابر محدودهٔ high/low هر کندل چک می‌شن (نه فقط close) — دقیقاً مثل رفتار واقعی سفارش OCO روی صرافی؛ اگه هر دو در یک کندل لمس بشن، فرض محافظه‌کارانه (SL زودتر) اعمال می‌شه
- کارمزد (نرخ پیش‌فرض تخمینی، قابل‌تنظیم) و حداقل ارزش معامله (خطای SmallOrder) در نتیجه لحاظ می‌شن — سیگنال‌های کوچیک‌تر از حداقل رد می‌شن، نه گرد می‌شن
- انتخاب «بهترین استراتژی» بر اساس میانگین Sharpe Ratio روی همهٔ نمادهای تست‌شده (بازده تعدیل‌شده با ریسک، نه فقط سود خام) — هم‌راستا با سطح ریسک متعادل پروژه

⚠️ **نرخ کارمزد (`fee_rate` در `BacktestConfig`) یک مقدار تخمینیه** — قبل از اتکا به نتایج بک‌تست برای تصمیم نهایی، نرخ دقیق کارمزد حساب خودتون رو از پنل نوبیتکس چک و در `BacktestConfig` اصلاح کنید.

## مدیریت ریسک (فاز ۵)

`src/nobitex_bot/risk/risk_manager.py` یک دروازهٔ واحد (`RiskManager.evaluate(...)`) پیاده می‌کنه که **هر** سیگنال معاملاتی قبل از رسیدن به فاز ۷ (اجرای واقعی) باید ازش عبور کنه:

1. **Position Sizing** بر اساس ٪ ثابت از سرمایه (`risk_per_trade_pct`, پیش‌فرض ۲٪) — نه مقدار ثابت؛ فاصلهٔ SL از قیمت ورود تعیین می‌کنه پوزیشن چقدر بزرگ باشه (همون فرمول بک‌تست، در `risk/position_sizing.py`، تا منطق بین بک‌تست و اجرای زنده یکسان بمونه)
2. **محدودیت حداکثر ضرر روزانه** (پیش‌فرض ۵٪) — با رسیدن به این حد، `evaluate` تا شروع روز تقویمی بعد همهٔ سیگنال‌ها رو رد می‌کنه
3. **محدودیت تعداد معاملات هم‌زمان باز** (پیش‌فرض ۳)
4. **قید BadPrice** — اگه قیمت پیشنهادی سیگنال بیش از ۳۰٪ با قیمت لحظه‌ای بازار فاصله داشته باشه، رد می‌شه
5. **قید SmallOrder** — اگه اندازهٔ پوزیشن محاسبه‌شده کمتر از حداقل ارزش معامله (۳ میلیون ریال / ۱۱ تتر) باشه، رد می‌شه

هر SL/TP از قبل در `TradeSignal` (فاز ۳) اجباریه — این فیلدها اختیاری نیستن، پس این‌جا دوباره enforce نمی‌شه.

## Paper Trading روی Testnet (فاز ۶)

```bash
# .env: NOBITEX_ENV=testnet و NOBITEX_API_TOKEN=<توکن Testnet>
python scripts/run_paper_trading.py --resolutions 15,60,240 --interval-minutes 15 --approval manual
```

جریان کامل: اسکن بازارها (روی بازار **واقعی**، نه Testnet) → سیگنال استراتژی → دروازهٔ مدیریت ریسک (فاز ۵) → **تاییدیهٔ انسانی** (پیش‌فرض: پرسش دستی در ترمینال؛ با فعال‌کردن بله/تلگرام از فاز ۸ جایگزین می‌شه) → ثبت سفارش ورود + سفارش OCO خروج **روی Testnet** → ثبت نتیجه در `data/paper_trading.sqlite`.

می‌شه هم‌زمان چند تایم‌فریم رو برای هر ۳ استراتژی تست کرد (`--resolutions 15,60,240`) — هر ترکیب (استراتژی، تایم‌فریم) یک `StrategyTrack` مستقل با سرمایه/مدیریت‌ریسک/پوزیشن‌های باز خودشه، دقیقاً مثل چند بک‌تست زنده و موازی. اسکن فرصت‌ها روی یک تایم‌فریم مرجع (`--scan-resolution`) مشترکه تا API چندبار صدا زده نشه.

```bash
python scripts/paper_trading_report.py   # گزارش PnL/Win Rate هر ترکیب (استراتژی@تایم‌فریم)، قابل‌مقایسه با گزارش بک‌تست
```

### اجرا روی GitHub Actions (بدون نیاز به VPS یا کارت بین‌المللی)

به‌جای اجرای `run_paper_trading.py` روی سیستم شخصی، می‌شه گیت‌هاب خودش هر ۱۵ دقیقه یک چرخه رو مجانی اجرا کنه — فایل `.github/workflows/paper-trading.yml` این کارو می‌کنه. فقط باید چندتا **GitHub Secret** (توکن‌ها) تنظیم کنید — راهنمای کامل و ساده در پیام جدا فرستاده شده. نکات مهم این مسیر:

- چون هیچ ترمینال زنده‌ای برای پرسیدن «تایید می‌کنید؟» وجود نداره، اینجا حتماً باید `--approval messaging` (بله/تلگرام) باشه، نه دستی.
- حافظهٔ ربات (پوزیشن‌های باز، لاگ تصمیم‌ها) توی یک شاخهٔ مخصوص به اسم `paper-trading-state` ذخیره می‌شه که مستقیم توی گیت‌هاب قابل دیدنه.
- داشبورد وب فاز ۸ روی GitHub Actions بالا نمی‌مونه (Actions برای اجرای کوتاه‌مدت زمان‌بندی‌شده‌ست، نه میزبانی وب‌سرور دائمی) — برای دیدن وضعیت از فایل‌های artifact هر اجرا یا اجرای موقت داشبورد روی سیستم خودتون (با کپی حافظهٔ همون شاخه) استفاده کنید.
- ⚠️ کلید/توکن‌ها فقط باید در GitHub Secrets باشن، نه در فایل `.env` محلی یا داشبورد — چون شاخهٔ `paper-trading-state` برای هرکسی که به این ریپو دسترسی داره قابل مشاهده‌ست.

### نکات ایمنی و طراحی مهم فاز ۶

- ⚠️ **`PaperTradingRunner` عمداً اگه `NOBITEX_ENV` روی `production` باشه، قبل از هر کاری خطا می‌ده و متوقف می‌شه** — فاز ۷ (پول واقعی) هنوز نیاز به تایید صریح شما داره.
- **دادهٔ بازار همیشه از بازار واقعی خونده می‌شه، نه Testnet** — endpointهای عمومی (`market/stats`, `market/udf/history`, `orderbook`) بدون توکن و بدون ریسک در دسترسن؛ فقط ثبت سفارش (`OrderExecutor`) به Testnet وصل می‌شه. این‌طوری سیگنال‌ها و برخورد SL/TP بر اساس رفتار واقعی بازار سنجیده می‌شن، نه دادهٔ احتمالاً غیرواقعی Testnet.
- **idempotency سفارش**: هر سفارش قبل از ارسال با یک `clientOrderId` تازه در جدول `order_intents` به‌عنوان `pending` ثبت می‌شه. اگه پاسخ صرافی `DuplicateOrder` باشه، به‌جای ارسال دوباره، وضعیت واقعی از صرافی استعلام می‌شه — درسی از باگ‌های فاز ۰.
- ⚠️ **این sandbox به نوبیتکس دسترسی شبکه نداره** — کل منطق با یونیت‌تست mock/synthetic تایید شده، ولی schema دقیق body سفارش‌ها (به‌خصوص فیلدهای OCO) باید روی Testnet واقعی verify بشه؛ فقط `place_order` در `exchange/client.py` نیاز به اصلاح داره اگه فرمت فرق داشت.
- طبق سند پروژه، Paper Trading باید **حداقل چند روز/هفته** قبل از فاز ۷ ادامه پیدا کنه.

## لاگ‌گیری، اعلان، و داشبورد وب (فاز ۸)

```bash
python scripts/run_dashboard.py --host 127.0.0.1 --port 5000
```

اولین بار که وارد می‌شید، هر رمزی که بدید «رمز اصلی» شما می‌شه (برای رمزنگاری کلیدها) — گمش نکنید. سه صفحه:

- **وضعیت**: سرمایهٔ مجازی/تعداد پوزیشن باز/وضعیت توقف ریسک روزانه برای هر ترکیب استراتژی×تایم‌فریم + آخرین تصمیم‌های ثبت‌شده (علت‌یابی)
- **معاملات**: پوزیشن‌های باز و تاریخچهٔ بسته‌شده‌ها
- **تنظیمات**: کلید API نوبیتکس + توکن‌های تلگرام/بله (رمزنگاری‌شده با Fernet، کلید از رمز اصلی با PBKDF2 مشتق می‌شه)، و **بخش مدیریت ریسک دستی** (درصد ریسک هر معامله، حداکثر ضرر روزانه، حداکثر معاملات هم‌زمان، حداکثر انحراف قیمت) — تغییرات بدون نیاز به ری‌استارت ربات، در چرخهٔ بعدی `run_once` اعمال می‌شن.

نکات کلیدی طراحی:

- **حالت اجرا: نیمه‌خودکار.** به‌جای تایید دستی در ترمینال، `MessagingApprovalGate` سیگنال رو با جزئیات (نماد، جهت، SL/TP، دلیل) به بله/تلگرام می‌فرسته و منتظر پاسخ متنی «تایید»/«رد» می‌مونه؛ بدون پاسخ در مهلت مشخص، پیش‌فرض **رد**ه (ایمن‌ترین حالت). دکمهٔ inline استفاده نشده چون schema دقیقش بین بله/تلگرام ممکنه فرق کنه و از این sandbox قابل‌تایید نبود — پاسخ متنی روی هر دو پلتفرم بدون فرض اضافه کار می‌کنه.
- **هم بله هم تلگرام** از طریق `CompositeNotifier` هم‌زمان قابل‌فعال‌سازی‌ان (`src/nobitex_bot/notifications/`).
- **داشبورد و ربات دو process جدان** — فقط از طریق فایل‌های مشترک (`paper_trading.sqlite`، `status.json`، `decisions.jsonl`، `risk_config.json`) با هم حرف می‌زنن؛ برای اسکریپت‌های headless مثل `run_paper_trading.py` که نمی‌تونن رمز اصلی رو از session داشبورد بگیرن، `NOBITEX_MASTER_PASSWORD` در `.env` لازمه تا کلید ذخیره‌شده در داشبورد رو بخونن.
- ⚠️ آدرس API بله (`tapi.bale.ai` در `notifications/bale.py`) بر پایهٔ دانش عمومی گذاشته شده و از این sandbox قابل تایید نبود — قبل از استفادهٔ واقعی از مستندات رسمی ربات بله verify کنید.
- ⚠️ اگه داشبورد رو روی VPS با `--host 0.0.0.0` در دسترس بیرون قرار می‌دید، حتماً `NOBITEX_FLASK_SECRET_KEY` رو در `.env` تنظیم کنید و پشت HTTPS (مثلاً یک ری‌ورس پروکسی) بذاریدش — این داشبورد خودش TLS نداره.

│   ├── base.py              # رابط پایه Strategy + TradeSignal
│   ├── trend_momentum_volume.py
│   ├── mean_reversion.py

│   └── registry.py          # رجیستری پلاگین‌مانند
├── backtest/
│   ├── engine.py            # شبیه‌سازی معامله (بدون look-ahead، با کارمزد/SmallOrder)
│   ├── metrics.py            # Win Rate، Max Drawdown، Sharpe Ratio

## نکات مهم دربارهٔ فاز ۱

- ⚠️ **فقط خلاصهٔ prompt پروژه در دسترس بوده، نه فایل کامل مستندات رسمی نوبیتکس.** مقادیر method/path/rate-limit در `exchange/endpoints.py` دقیقاً از همون خلاصه گرفته شدن. قبل از فاز ۶ (Paper Trading روی Testnet) حتماً یک تست دستی واقعی روی `market/stats` و `market/udf/history` بزن و در صورت اختلاف (مثلاً متد HTTP یا نام فیلد پاسخ)، فقط کافیه `endpoints.py` رو اصلاح کنی — بقیهٔ کد به این جزئیات وابسته نیست.
- آدرس Testnet در سند به‌صورت `testnetapiv2.nobitex.ir` اومده بود؛ در تحقیق فاز ۰ نسخهٔ `testnetapi.nobitex.ir` (بدون v2) هم دیده شد — این هم باید موقع فاز ۶ verify بشه (از طریق env قابل تغییره، نیازی به تغییر کد نیست).
- تمام مقادیر پولی با `Decimal` پردازش می‌شن؛ در SQLite هم به‌صورت TEXT ذخیره می‌شن (نه REAL) تا هیچ گرد‌کردن اعشاری اتفاق نیفته.
- Rate limiting به‌صورت per-endpoint (sliding window) پیاده شده و در پاسخ ۴۲۹ دقیقاً به مقدار `backOff` سرور صبر می‌کنه (نه یک عدد ثابت حدسی).
- درس‌های فاز ۰ (partial fill، duplicate order، rate-limit circuit breaker) در فازهای ۵ و ۷ اعمال می‌شن؛ لایهٔ داده فعلی فقط endpointهای عمومی (بدون توکن) رو پوشش می‌ده.

## نکات مهم دربارهٔ فاز ۲

- اندیکاتورها برای محاسبه به `float` تبدیل می‌شن (کتابخونه‌های عددی با `Decimal` کار نمی‌کنن)؛ این فقط برای *تحلیل/سیگنال* استفاده می‌شه — هر عددی که قراره به‌عنوان قیمت/مقدار سفارش به صرافی ارسال بشه (فاز ۵ به بعد) همچنان از داده‌ی Decimal اصلی (نه خروجی اندیکاتور) محاسبه می‌شه.
- امتیاز ترکیبی اسکنر (نوسان/حجم/سیگنال) بین بازارهای اسکن‌شده در هر بار اجرا نرمالایز می‌شه، پس قابل‌مقایسه بین دفعات مختلف اجرا نیست — فقط رتبه‌بندی نسبی همون یک اسکن معتبره.

## شروع سریع — اجرای ۲۴/۷ روی GitHub Actions

### مرحلهٔ ۱: ایجاد توکن تلگرام

1. پیام دهید به `@BotFather` در تلگرام
2. `/newbot` را بفرستید و نام ربات رو وارد کنید (مثلاً "MyTradingBot")
3. توکنی مثل این دریافت خواهید کرد: `123456789:ABCDEFghijklmnop...`
4. توکن را **ذخیره کنید** (مثل رمز عبور رفتار شود)

### مرحلهٔ ۲: دریافت Chat ID خود

1. ربات جدیدی که ساختید را **پیام دهید** (تا تلگرام شناسایی‌اش کند)
2. این URL را در مرورگر باز کنید:
   ```
   https://api.telegram.org/bot<توکن_شما>/getUpdates
   ```
   (توکن را جایگزین `<توکن_شما>` کنید)
3. عددی مثل `"chat": {"id": 12345678}` را جستجو کنید — این **Chat ID** شماست

### مرحلهٔ ۳: اضافه‌کردن GitHub Secrets

1. به https://github.com/kianoshs-sudo/bot-trade بروید
2. **Settings** → **Secrets and variables** → **Actions** کلیک کنید
3. **New repository secret** کلیک کنید و این‌ها را یکی یکی اضافه کنید:

| نام Secret | مقدار |
|-----------|-------|
| `NOBITEX_API_KEY` | کلید API Testnet نوبیتکس |
| `NOBITEX_API_SECRET` | Secret کلید API |
| `TELEGRAM_TOKEN` | توکن بات تلگرام (از مرحلهٔ ۱) |
| `TELEGRAM_CHAT_ID` | Chat ID (از مرحلهٔ ۲) |

### مرحلهٔ ۴: فعال‌کردن Workflow

فایل `.github/workflows/paper_trading.yml` از قبل موجود است و:
- هر ۱۵ دقیقه یکبار اجرا می‌شود (رایگان)
- بازار را اسکن می‌کند
- اگر سیگنال پیدا کند، پیام تلگرام می‌فرستد
- منتظر تایید/رد شما است

### مرحلهٔ ۵: آزمایش دستی

از برگهٔ **Actions** روی گیت‌هاب:
1. **Paper Trading Loop** را کلیک کنید
2. **Run workflow** را کلیک کنید
3. ۲-۳ دقیقه صبر کنید
4. پیامی از ربات تلگرام باید دریافت کنید
